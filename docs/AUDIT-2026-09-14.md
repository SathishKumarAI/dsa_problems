# Audit — single source of truth, and the road to a product

Read with `docs/BACKLOG.md`. This document is **findings + a proposed plan**, not shipped work.
Nothing here has been implemented. Every number below was measured on 2026-09-14 at `1e3c789`.

---

## 0. What the prompt assumed, and what is actually true

The redesign brief that triggered this audit describes a repo where content is scattered across
screens with no canonical record. **That is not this repo.** Correcting the premises first, because
half the proposed work is already shipped and rebuilding it would be pure loss:

| The brief says | Measured reality |
|---|---|
| "no single place that answers *everything about Detect a Cycle*" | `docs/learn/<id>.md` is exactly that page, generated by `npm run docs:learn`, reachable at `#/learn/<id>` |
| "a problem can appear in more than one journey with no guarantee copy stays in sync" | `Journey.problemId` is a reference; `data/journeys/cycle-detect.ts` imports `problem` and reuses `problem.statement`, `problem.hints`, `problem.whyNow` rather than restating them |
| "resources per problem would drift" | Already solved: `Reference[]` hangs off `Pattern`, with a comment in `src/data/types.ts` arguing exactly this decision |
| "deduplication is a cleanup task" | `src/data/problems.test.ts`, `src/engine/journeys.test.ts` and `scripts/learn-gaps.mjs --strict` already forbid the two known copy classes (B1, B63) |
| "approach comparator — a first-class view" | `src/lib/ladder.ts` already builds one ladder from two sources so the reasoning is never written twice |
| "command palette, focus mode, keyboard shortcuts, copy-to-clipboard" | All shipped — `features/search/palette.tsx`, `lib/shortcuts.ts`, `components/code-block.tsx` |

So the useful question is not "how do we introduce a canonical record" — it exists — but **where
does the canonical record still leak, and what is the app unable to show because of it.**

## 1. Findings

### D1 — `docs/learn/` is a 4.47 MB build artifact committed to git, 69% of it a byte-for-byte copy

```
deep bytes spliced verbatim into learn:  3,067,083
docs/learn total bytes:                  4,472,882
.git:                                    8.8 MB
tracked files under docs/learn:          128
```

`scripts/gen-learn.mjs` splices `docs/deep/<id>_explained.md` in **verbatim** and assembles the rest
from `src/data/problems/**`. Every byte in `docs/learn` is therefore a copy of something else in the
repo, and CI already carries a step whose entire job is to prove that (`docs/learn is regenerated,
not hand-edited`). The folder is a derived artifact wearing a source file's clothes. B65 plans ~20
more batches of 20 problems; each regeneration rewrites a large fraction of those 4.5 MB into
history.

**Severity: high. Cost to fix: three lines.** Gitignore it; generate it in `predev` / `prebuild`.
The CI drift check collapses into "generate, then build". Nothing a reader sees changes.

The purer alternative — delete the generator, compose the learn page at runtime from the deep doc
plus the data the app already imports — is **not** recommended: it rewrites 482 working, tested
lines as a React component to save one build step.

### D2 — The app's ladder shows fewer approaches than the learn page teaches, on 45 of 82 problems

```
deep doc has MORE approaches than the app's ladder:  45
equal:                                                37
fewer:                                                 0
```

Rung counts (`alternatives` + the optimal) across all 127 problems: **2 rungs on 55 problems, 3 on
42, 4 on 10, 5 on 20.** Approach sections across the 82 deep docs: **2 on 5, 3 on 18, 4 on 23, 5 on
34, 6 on 2.**

This is *disclosed* drift, not silent drift. `docs/deep/README.md` permits a document to teach a
rung the data lacks, requires the heading to say so, and `scripts/learn-gaps.mjs --strict` reports
`Documents that add approaches without saying so — 0`. The gate works.

But the consequence is the gap the brief actually put its finger on: **`cycle-detect` teaches four
approaches in prose and the problem page can offer two**, because the nested walk and the
value-marking variant exist only as Markdown. The app cannot compare what it cannot address.

The brief asks for "six genuinely different angles". On 45 problems that content already exists. It
is unaddressable, not missing.

### D3 — Two `Resource` types

`src/engine/types.ts` has `Resource { label, url }` on a Journey. `src/data/types.ts` has
`Reference { title, href, kind, note }` on a Pattern, with a long comment arguing why references
belong to a pattern. Two names, two shapes, one concept. `Reference` is strictly richer, and its
`note` field — "why THIS source" — is the thing that makes a link worth following.

### D4 — `docs/RESOURCES.md` is the best teaching artifact in the repo and has no route to it

The six array ideas and the five linked-list moves, each with the tell in the statement, the problem
to learn it on, and the classic mistake — 115 lines of tables, covering **2 of 10 patterns**.
Nothing in `src/` reads it. `Pattern.references` (30 links) renders only as a strip in the
pattern-list header (`problem-list.tsx:68`). There is no `#/resources` route.

### D5 — Six planning documents answer "what next"

`BACKLOG.md` (203), `ROADMAP.md` (141), `PRD.md` (190), `LEARN-PLAN.md` (160), `LEARN-GAPS.md` (171,
generated), `SPEC-CHECKLIST.md` (101). `CLAUDE.md` points a session at `BACKLOG.md` only — the
honest signal about which of the six are load-bearing.

### D6 — Every code block on the site is Python-first; the only thing the site can run is JavaScript

`Code.python` is required, `java` / `cpp` optional. The challenge editor
(`features/journey/challenge-editor.tsx`) evaluates the learner's code with `new Function` inside a
Web Worker — correct, well documented, and JavaScript-only. A learner reading Python all day writes
JavaScript to be graded.

Meanwhile `scripts/verify-deep.mjs` extracts the last python block from **every** deep document,
runs it, and requires it to report that its approaches agreed — in CI, on every PR. There are 82
verified, self-checking Python scripts in this repo that no reader can execute.

### D7 — Smaller, factual

| # | Finding |
|---|---|
| D7a | No `Note` entity. `src/lib/store.ts` owns nine key families; none is notes. |
| D7b | The palette indexes problems and journeys only. Hints, rungs, notes and references are not searchable. (Acts and subtitles are excluded **on purpose** — the disclosure rule — and must stay excluded.) |
| D7c | `Problem.pattern` is one string. `three-sum` is two-pointers *and* sorting; the folder is the key, so a second pattern has nowhere to go. |
| D7d | Themes are `dark \| light \| system`. No sepia, no reading typeface. |
| D7e | No problem-id chip on the problem header — the canonical-record idea is structural but invisible. |
| D7f | `docs/statistics/` (6 files, its own `SYLLABUS.md` and `verify-statistics.mjs`) is a different subject living in a DSA repo. |
| D7g | Stray `rewrite.cpython-312.pyc` at the repo root; `__pycache__/` is ignored, the root `.pyc` is not. |

## 2. The model, stated once

The repo already follows it. Writing it down so the next thirty batches cannot drift from it:

```
Problem (src/data/problems/<pattern>/<id>.ts)   <- THE canonical record
  - rungs:  the optimal (top level) + alternatives[], in build order
  - hints, constraints, examples, arc, whyNow
  - id:     the only key anything else uses

Journey    (src/data/journeys/<id>.ts)      -> problemId; imports the Problem, never copies it
Deep doc   (docs/deep/<id>_explained.md)    -> the authored PROSE for those rungs
Learn page (docs/learn/<id>.md)             -> GENERATED: Problem + deep doc. Owns nothing.
Pattern    (src/data/patterns.ts)           -> owns references[]; problems point at it
Note       (localStorage)                   -> the one per-user entity, never exported with content
```

**One rule, and it is the only one that matters:** a rung is a record in the Problem file; prose
about a rung lives in the deep doc, keyed to that rung; neither may invent a rung the other has not
got. Today the deep doc may — disclosed — and that disclosure is precisely what the app cannot
render.

## 3. The plan

Five phases, each a branch and a PR. Phase 0 changes nothing a reader sees and should land first,
because everything after it is cheaper on a repo that has stopped copying bytes.

### Phase 0 — stop the copying (no new features)

| Item | Change | Size |
|---|---|---|
| **B72** | Gitignore `docs/learn/`; add `predev` / `prebuild` / `pretest:ui` running `npm run docs:learn`. The CI "regenerated, not hand-edited" step becomes "generate, then build". Removes 4.47 MB of derived bytes from the working tree and stops ~20 batches of history churn. | S |
| **B73** | Delete `engine/types.ts Resource`; `Journey.resources` takes `Reference` from `data/types.ts`. One shape, one renderer, and `note` becomes available on journey links. | S |
| **B74** | Fold `ROADMAP.md`, `LEARN-PLAN.md` and `SPEC-CHECKLIST.md` into `BACKLOG.md` (a themes section and a definition-of-done section). Keep `PRD.md` (the why) and `LEARN-GAPS.md` (generated). `CLAUDE.md`'s table loses three rows. | S |
| **B75** | `scripts/graph.mjs` emits `docs/graph.json`: problem → pattern → rungs → journey → deep doc → edge cases → references, plus `--check` for orphans, dangling ids and rung-key mismatches. One file an agent or a future UI reads instead of grepping ten directories. Feeds B9's pattern graph for free. | M |
| **B76** | Delete `rewrite.cpython-312.pyc`; decide `docs/statistics/` — its own repo, or a row in `CLAUDE.md` saying it lives here on purpose. | XS |

### Phase 1 — make a rung addressable (the single-source-of-truth change)

The phase that unlocks everything in the brief that is not already shipped.

| Item | Change | Size |
|---|---|---|
| **B77** | Add `key: string` to `Solution`, and a key for the top-level optimal. Rung keys become stable ids: `brute`, `set`, `floyd`, `brent`. Journeys already have `Act.key` — reuse that vocabulary so a journeyed and a non-journeyed problem name their rungs identically. | M |
| **B78** | Deep-doc headings bind to rung keys: `## Approach 3: Node marking {#mark}`. `scripts/learn-gaps.mjs` gains one check — **every `## Approach` maps to a rung key, and every rung has a section.** A document may still add a rung; adding it now means adding the record too. | M |
| **B79** | **Promote the disclosed additions.** For the 45 problems where the deep doc teaches more than the data holds, lift each extra approach into `alternatives[]` with its code, complexity and summary. The prose does not move; only a record is created for it. The ladder then shows what the learn page teaches, on every problem, by construction. Batched 20 at a time — B65's unit. | XL |
| **B80** | **Pilot first, on three problems only** — `cycle-detect`, `pair-sum`, `single-number`. Prove B77–B79 end to end, then write the template. Nothing else is touched until the pilot PR is reviewed. | M |
| **B81** | **The template.** `docs/PROBLEMS.md` gains a rung-record template; `docs/deep/README.md` gains the key-binding rule; a new `templates/problem.ts` skeleton carries every field and the six-angle checklist — fast answer, memory trade, mutate-in-place, brute-force baseline, recursive framing, known trick. Future batches copy this instead of the last problem that looked similar. | S |

### Phase 2 — run the Python that is already verified

| Item | Change | Size |
|---|---|---|
| **B82** | Pyodide in a Worker, **lazy** — nothing downloads until the learner presses Run. Every python block on a learn page and every rung's Python tab gets a Run button; output renders under the block. | L |
| **B83** | Per-problem playground seeded from the deep doc's *Full Runnable Script* — the same script `verify-deep.mjs` executes in CI. Zero new content: 82 problems get a working, self-checking Python sandbox the day the runner lands. | M |
| **B84** | The challenge act accepts Python as well as JavaScript, judged against the same `ChallengeCase[]`. B23's "`node:vm` is not a sandbox" argument does not apply — Pyodide is a wasm sandbox in the learner's own tab and nothing leaves it. | L |

Honest cost: Pyodide is ~6 MB of wasm. Lazy-loading means a reader who never presses Run pays
nothing, and the site stays a static build with no backend — the property B24 has been protecting.

### Phase 3 — the front-end surface the brief asks for

Only what is not already shipped, and nothing that moves what exists.

| Item | Change | Size |
|---|---|---|
| **B85** | **`#/resources` route.** Pattern-grouped: each pattern's `references[]` with its `note`, plus the problems carrying that pattern. `docs/RESOURCES.md`'s tables become pattern-level `playbook` rows in `patterns.ts` — the idea, the tell, where to learn it, the classic mistake — so the best writing in the repo reaches a screen. Extending it to the other 8 patterns is then filling a table, not writing a document. | L |
| **B86** | **Per-problem notes.** One store key `notes:<problemId>`, one autosaving textarea in the problem page's drawer. Never bundled into the progress export (B3) — notes are the one per-user entity. | S |
| **B87** | **Approach comparator.** The ladder gains a compare mode: pick two rungs, see complexity, summary and code side by side with the differing lines marked. Falls out of B77 — rungs now have keys to select by. | M |
| **B88** | **Search the record, not just its title.** Index hints, rung names and summaries, notes and references. **The disclosure rule is not weakened:** a rung is indexed only when the ladder would show it (`ladder.capped === false`), exactly as `problem-detail.tsx` already gates the arc. | M |
| **B89** | Problem-id chip in the problem header (`id: cycle-detect`, monospace, click to copy). Makes the canonical record visible. | XS |
| **B90** | Sepia theme and a serif reading face for prose, both behind the existing prefs store. Long reading sessions are the actual use. `theme-provider.tsx` already resolves three values; sepia is a fourth token set in `index.css`, not new machinery. | M |
| **B91** | **Printable reference sheet** per problem — statement, every rung, hints — generated from the same records, so there is no export copy to keep in sync. `@media print` over the existing learn page is most of it. | S |

### Phase 4 — scale

B79's remaining batches, then B65 continues toward the LeetCode top 500 on a contract where the
document and the data cannot disagree, and `graph.mjs --check` fails the PR if they do.

## 4. Deliberately not proposed

| Rejected | Why |
|---|---|
| Migrating `Problem.pattern` to `patterns[]` | The folder is the key; 127 files would move so a problem can carry a second tag. If cross-pattern filtering is wanted, `alsoPatterns?: string[]` is additive and costs one field. Not worth a migration yet. |
| A relational backend | B24 already says: a real backend when the need is real. Nothing in the brief needs one. A static build with localStorage and an optional JSON export is the right shape for a site one person publishes for free. |
| Runtime composition of the learn page (deleting `gen-learn.mjs`) | Rewrites 482 tested lines as a component to save a build step. B72 gets the same benefit for three lines. |
| Scroll-collapsing header, hero motifs, glass panels, mesh gradients | `docs/DESIGN.md` is a six-step type scale with roles and one palette in `index.css`, and `docs/UX-AUDIT.md` holds 28 measured findings against it. A visual direction imported from a mockup would regress a system that was measured into place. If a refresh is wanted it is its own audit, against `DESIGN.md`. |
| Offline / PWA caching | No stated need; the site is a static build and already cacheable. |
| Spaced repetition, confidence rating, pattern graph | Already B15, B10 and B9. Not re-filed. |
